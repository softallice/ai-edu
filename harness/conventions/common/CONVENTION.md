# 컨벤션 팩: common (전 사이트 공통)

> 모든 사이트에 항상 적용되는 기본 규칙입니다. 스택별 팩(`react-typescript`, `nexacro`, `egov-backend`)과 함께 로드됩니다.
> 출처: nkit `rules/common/*` + 하네스 `instructions/INSTRUCTIONS.md` 종합.

## 코드 스타일

- **KISS / DRY / YAGNI**: 작동하는 가장 단순한 해법 우선, 실제 반복이 있을 때만 추상화, 필요해지기 전 기능 구축 금지.
- **불변성**: 새 객체를 반환하고 원본 변경 금지. (단 Java/eGov의 `Map` 파라미터 패턴은 예외적으로 mutation 허용)
- **파일 구성**: 많은 작은 파일 > 적은 큰 파일. 200~400줄 권장, 800줄 최대. 기능/도메인별 구성.
- **함수**: <50줄 권장, 중첩 4레벨 이하. 조기 반환으로 중첩 회피.
- **명명**: 변수/함수 `camelCase`, 클래스/타입 `PascalCase`, 상수 `UPPER_SNAKE_CASE`, 불리언 `is/has/should/can` 접두사. 매직 넘버·하드코딩 금지.

## 에러 처리

- 모든 경계에서 명시적 처리. 조용히 삼키지 않기.
- UI는 사용자 친화 메시지, 서버는 상세 컨텍스트 로깅.

## 입력 검증 / 보안

- 시스템 경계에서 모든 외부 입력 검증(스키마 기반 선호), 빠른 실패.
- 하드코딩 시크릿 금지 → 환경변수. SQL은 파라미터 바인딩(`${}`/문자열 결합 금지).
- 외부 데이터(API 응답, 파일, 사용자 입력) 불신.

## 테스트

- 신규/수정 로직에 테스트 동반. 커버리지 80%+ 목표.
- TDD 권장: RED → GREEN → REFACTOR.

## Git / 커밋

- 형식: `<type>: <description>` (type: feat, fix, refactor, docs, test, chore, perf, ci)
- PR 전 빌드/린트/테스트/보안 점검.

## 작업 완료 체크리스트

- [ ] 읽기 쉽고 명명이 적절한가
- [ ] 함수 <50줄, 파일 <800줄, 중첩 ≤4
- [ ] 에러 처리·입력 검증 존재
- [ ] 하드코딩/시크릿 없음
- [ ] 테스트 동반(80%+)
