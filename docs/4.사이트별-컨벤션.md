# 사이트별 컨벤션 적용 가이드

사이트마다 코딩 컨벤션이 다른 환경(React-TS / Nexacro / 전자정부 백엔드)에서, **하네스는 공통 베이스**로 두고 **각 사이트가 필요한 컨벤션 팩만 골라 적용**하는 구조입니다. (PoC)

## 1. 구조

```
harness/
  conventions/
    common/CONVENTION.md            # 전 사이트 공통 (하네스 기본 instructions에 포함)
    react-typescript/CONVENTION.md   # TS + React (TanStack/shadcn 스택)
    spring-boot/CONVENTION.md        # 모던 Spring Boot REST + JPA
    nexacro/CONVENTION.md
    egov-backend/CONVENTION.md       # 전자정부 일반표준 + NDSERP 예시
    profiles.json                    # 사이트 → 팩 매핑
    README.md
  scripts/apply-convention.cjs       # 사이트 overlay 생성기
  commands/apply-convention.md       # /apply-convention 커맨드
  examples/
    site-react-ts/                   # 생성 예시
    site-nexacro-egov/
```

## 2. 적용 모델

- **하네스 = 글로벌 베이스**: 에이전트·커맨드·PDCA·`common` 컨벤션을 모든 사이트가 공유. 하네스를 `~/.config/opencode/`에 설치(또는 링크).
- **사이트 레포 = 오버레이**: 각 레포 루트에 `opencode.json`+`AGENTS.md`를 두고 필요한 팩을 `instructions`로 지정. OpenCode가 cwd에서 위로 config/AGENTS.md를 **머지**하므로, 사이트 레포에서 `opencode` 실행 시 베이스 + 사이트 팩이 함께 적용됩니다.

## 3. 사용법

### 가장 쉬운 방법 — 생성기
```bash
# 팩 직접 지정 (common 자동 포함)
node <harness>/scripts/apply-convention.cjs <사이트레포> react-typescript
node <harness>/scripts/apply-convention.cjs <사이트레포> nexacro egov-backend

# 프로파일로 지정
node <harness>/scripts/apply-convention.cjs <사이트레포> --profile nexacro-egov
```
OpenCode 안에서는 `/apply-convention <사이트레포> nexacro egov-backend` 로도 가능합니다.

생성물: 사이트 레포에 `opencode.json`(팩 instructions) + `AGENTS.md`(요약). 이후 그 레포에서 `opencode` 실행 시 적용됩니다.

### 프로파일 (`conventions/profiles.json`)
| 프로파일 | 팩 |
|----------|-----|
| `react-site` | react-typescript |
| `spring-boot` | spring-boot |
| `react-spring` | react-typescript, spring-boot |
| `nexacro-egov` | nexacro, egov-backend |
| `egov-only` | egov-backend |

## 4. 컨벤션 팩 요약

| 팩 | 핵심 |
|----|------|
| **common** | KISS/DRY/YAGNI, 불변성, 작은 파일, 에러처리·입력검증, 테스트 80%+, 커밋 규칙 |
| **react-typescript** | TS strict(`any` 금지), 함수형+훅, **kebab-case 파일+named export**, TanStack(Router/Query/Table)·shadcn/ui·zustand·rhf+zod, `cn()`, Prettier/ESLint |
| **spring-boot** | `@RestController` 얇게/Service 트랜잭션/JpaRepository 계층, 생성자 주입, record DTO(엔티티 비노출)+Bean Validation, `@RestControllerAdvice` 전역 예외, REST URL |
| **nexacro** | `sPACKAGENAME`·`on_initEvent` 필수, `fnc_TransactionCall()`, `.xfdl`+`.xfdl.js` 동시 생성, Dataset 네이밍 |
| **egov-backend** | Controller/Service/DAO 계층, 생성자 주입, MyBatis `#{}` 바인딩(❌`${}`), 동적 SQL 화이트리스트 / (옵션) NDSERP 구체 규칙 |

## 5. PDCA·에이전트 연동

`pdca-orchestrator`는 실행 시작 시 활성 컨벤션 팩을 감지하고, 서브에이전트(planner/architect/build/reviewers)에 해당 팩 규칙을 프롬프트로 주입합니다. `design`은 구조·네이밍을, `do`는 코드 생성 규칙을, `check`는 팩의 MUST/❌ 규칙을 품질 게이트(L1/L2) 기준으로 사용합니다.

## 6. 리팩토링 적용 요소 (이번 PoC에서 구성)

| 요소 | 내용 |
|------|------|
| R1 | 컨벤션 팩 4종 + README 생성 |
| R2/R7 | 활성화 생성기(`apply-convention.cjs`) + `/apply-convention` 커맨드 |
| R3 | 하네스=글로벌 베이스 / 사이트=오버레이 배치, 예시 2종 |
| R4 | `common`을 하네스 기본 instructions에 편입, 스택 팩은 오버레이 전용 |
| R5 | `profiles.json` 사이트→팩 매핑 |
| R6 | 오케스트레이터에 컨벤션 주입 규칙 추가 |
| R8 | JSON·참조·팩·프로파일·overlay 검증 + `tsc` 통과 |

## 7. 확장 — 새 사이트/팩 추가

1. 새 팩: `conventions/<stack>/CONVENTION.md` 작성(기존 팩 형식 참고, 상세는 `@skills/...` 참조).
2. `profiles.json`에 조합 등록.
3. `/apply-convention <레포> <팩...>` 또는 `--profile <name>`로 적용.
