# 프론트엔드 교육용 템플릿 구조 (shadcn-admin 기반)

이 문서는 `ai-edu` 저장소 전체 구조를 상세히 분석하고, 그 위에 **[satnaing/shadcn-admin](https://github.com/satnaing/shadcn-admin)** 을 기반으로 구성한 `frontend/` 교육용 템플릿의 구조·스택·하네스 연동 방식을 정리합니다.

대상 독자는 React-TypeScript 트랙 수강생과, 템플릿을 유지·확장하는 강사/운영자입니다.

---

## 1. ai-edu 저장소 전체 구조

`ai-edu`는 **로컬 PC에서 인터넷 없이 동작하는 AI 코딩 에이전트 실습 환경**입니다. WSL + Ollama(로컬 LLM) + OpenCode(에이전트 CLI) + 하네스(설정 본체)로 구성되며, 이제 실습 산출물의 기준이 되는 `frontend/`·`backend/` 템플릿이 추가되었습니다.

```
ai-edu/
├─ README.md                  # 설치·실행·빠른 시작
├─ docs/                      # 교육 문서 (학습 순서대로 번호 부여)
│  ├─ 1.환경설정.md            # WSL·Java·Node·Ollama·OpenCode 런타임 설치
│  ├─ 2.PDCA-방법론.md         # 개발 방법론(품질 게이트 기반 루프)
│  ├─ 3.폐쇄망-GPU서버-아키텍처.md  # (심화) 서버·폐쇄망 확장
│  ├─ 4.사이트별-컨벤션.md      # 컨벤션 팩 적용 모델
│  ├─ 5.로컬교육-설치-활용.md   # 설치·실행·활용 핵심 가이드
│  └─ 6.프론트엔드-템플릿-구조.md  # (이 문서)
├─ harness/                   # OpenCode 하네스 — 에이전트 설정의 본체
├─ frontend/                  # ★ React-TS 교육용 템플릿 (shadcn-admin 기반)
└─ backend/                   # ★ Spring Boot REST 백엔드 템플릿
```

| 영역 | 역할 | 현재 상태 |
|------|------|-----------|
| `docs/` | 교육 문서 6종 | 작성 완료 |
| `harness/` | 모델·에이전트·커맨드·PDCA·컨벤션·MCP 설정 | 구성 완료 |
| `frontend/` | React-TS 실습 기준 템플릿 | shadcn-admin v2.2.1 기반 스캐폴딩 완료 |
| `backend/` | Spring Boot REST 실습 기준 템플릿 | Spring Boot 4.0.6 + Java 25 + Gradle, 빌드·테스트 통과 |

### 1.1 harness/ 구성 요약

하네스는 ECC(everything-claude-code)의 `.opencode` 구성을 OpenCode 전용으로 포팅하고, 멀티-티어 Anthropic 모델을 **로컬 Ollama `qwen2.5-coder:7b` 단일 모델**로 재구성한 것입니다.

| 영역 | 위치 | 개수 | 설명 |
|------|------|------|------|

| 에이전트 | `prompts/agents/*.txt` | 25 (+`build`) | 전문 에이전트 시스템 프롬프트 |
| 커맨드 | `commands/*.md` | 35 | 슬래시 커맨드 템플릿 |
| 플러그인 | `plugins/ecc-hooks.ts` | 1 | 11개 이벤트 훅 + 7개 도구 등록 |
| 도구 | `tools/*.ts` | 7 | run-tests / check-coverage / security-audit / format-code / lint-check / git-summary / changed-files |
| 스킬 | `skills/*/SKILL.md` | 11 | instructions로 로드되는 도메인 지식 |

## 2. frontend/ 템플릿 개요

`frontend/`는 satnaing/shadcn-admin(**v2.2.1**)을 **원본 그대로** 클론하여 구성한 React 관리자 대시보드 템플릿입니다. 수강생이 PDCA·컨벤션을 적용하며 기능을 추가/수정할 때의 **기준 코드베이스** 역할을 합니다.

### 2.1 기술 스택

| 분류 | 라이브러리 |
|------|-----------|
| 빌드 | **Vite** + `@vitejs/plugin-react` |
| 언어 | **TypeScript** (strict, project references: `tsconfig.app.json`/`tsconfig.node.json`) |
| UI | **shadcn/ui** (Radix UI 프리미티브 + `class-variance-authority`) |
| 스타일 | **Tailwind CSS v4** (`@tailwindcss/vite`, `tw-animate-css`) |
| 라우팅 | **TanStack Router** (파일 기반 + `@tanstack/router-plugin` 코드 생성) |
| 서버 상태 | **TanStack Query** (+ devtools) |
| 테이블 | **TanStack Table** |
| 폼/검증 | **react-hook-form** + **zod** (`@hookform/resolvers`) |
| 클라이언트 상태 | **zustand** |
| 인증 | `stores/auth-store`(zustand) 기반 — 외부 인증 SDK 없이 동작 |
| HTTP | **axios** |
| 차트 | **recharts** |
| 아이콘 | `lucide-react`, `@radix-ui/react-icons` |
| 기타 UI | `cmdk`(커맨드 팔레트), `sonner`(토스트), `react-day-picker`, `input-otp`, `react-top-loading-bar` |
| 테스트 | **Vitest** (browser mode, Playwright provider) + `vitest-browser-react` |
| 품질 | ESLint(flat config), Prettier(+import sort/tailwind), `knip`(미사용 코드 검출) |
| 목 데이터 | `@faker-js/faker` |

### 2.2 주요 스크립트 (`package.json`)

```bash
pnpm dev            # 개발 서버 (Vite)
pnpm build          # tsc -b && vite build (타입체크 후 번들)
pnpm lint           # ESLint
pnpm format         # Prettier 적용 / format:check 로 검사
pnpm knip           # 미사용 export·의존성 검출
pnpm test           # Vitest (브라우저 헤드리스)
pnpm test:coverage  # 커버리지 포함 실행
pnpm test:browser:install  # 최초 1회 Playwright chromium 설치
```

> 패키지 매니저는 원본과 동일하게 **pnpm**(`pnpm-lock.yaml` 존재)을 사용합니다.

## 3. frontend/ 디렉터리 상세

```
frontend/
├─ index.html                 # SPA 진입 HTML
├─ vite.config.ts             # Vite + router-plugin + tailwind 설정
├─ components.json            # shadcn/ui CLI 설정 (별칭·스타일)
├─ tsconfig*.json             # TS project references
├─ eslint.config.js           # ESLint flat config
├─ knip.config.ts             # 미사용 코드 검출 설정
├─ public/                    # 정적 자산(이미지 등)
└─ src/
   ├─ main.tsx                # 앱 부트스트랩 (Router + QueryClient + Provider 트리)
   ├─ routeTree.gen.ts        # ★ router-plugin 자동 생성 (수정 금지)
   ├─ routes/                 # 파일 기반 라우트 정의
   ├─ features/               # 도메인(기능)별 화면·로직
   ├─ components/             # 공용 컴포넌트 (ui / layout / data-table)
   ├─ context/                # 전역 Provider (theme/font/direction/layout/search)
   ├─ stores/                 # zustand 스토어 (auth 등)
   ├─ hooks/                  # 공용 훅
   ├─ lib/                    # 유틸 (utils, cookies, error 핸들러)
   ├─ config/                 # 폰트 등 설정
   ├─ assets/                 # 브랜드/커스텀 아이콘
   ├─ styles/                 # 전역 스타일(Tailwind)
   └─ test-utils/             # 테스트 헬퍼
```

### 3.1 라우팅 (`src/routes/`) — TanStack Router 파일 기반

파일 트리가 곧 URL 구조이며, `@tanstack/router-plugin`이 `routeTree.gen.ts`를 자동 생성합니다. **`routeTree.gen.ts`는 손으로 수정하지 않습니다.**

```
routes/
├─ __root.tsx                 # 루트 레이아웃 (Provider·devtools)
├─ (auth)/                    # 인증 화면 그룹 (URL 경로에 미반영되는 그룹)
├─ (errors)/                  # 에러 페이지 그룹
├─ _authenticated/            # 인증 필요 영역 (레이아웃 가드)
│  ├─ route.tsx               # 인증 레이아웃 (사이드바·헤더)
│  ├─ index.tsx               # 대시보드 (/)
│  ├─ tasks/  users/  apps/  chats/  help-center/  errors/
│  └─ settings/               # 프로필/계정/외관/알림/표시 탭
```

- `(폴더명)` 은 **경로 그룹**(URL에 미포함), `_authenticated` 의 `_` 접두사는 **레이아웃(pathless) 라우트**를 의미합니다.
- 화면 실제 구현은 `routes/`가 아니라 `features/`에 있고, 라우트 파일은 해당 feature 컴포넌트를 연결만 합니다.

### 3.2 기능 모듈 (`src/features/`) — 도메인별 구성

각 기능은 화면·하위 컴포넌트·목 데이터를 자기완결적으로 보유합니다. 이 구조가 컨벤션의 "기능/도메인별 폴더(`features/...`)" 규칙과 일치합니다.

| feature | 내용 |
|---------|------|
| `dashboard` | 메인 대시보드(차트·통계 카드) |
| `tasks` | TanStack Table 기반 작업 목록(필터·페이지네이션·열 가시성) |
| `users` | 사용자 관리 테이블 + 다이얼로그(CRUD UI) |
| `apps` | 앱 연동 카드 그리드 |
| `chats` | 채팅 UI |
| `settings` | 프로필/계정/외관/알림/표시 등 탭 폼(react-hook-form + zod) |
| `auth` | sign-in / sign-up / forgot-password / otp 화면 |
| `errors` | 401/403/404/500/503 등 에러 화면 |

> **실습 권장 진입점**: `features/tasks`(테이블+URL 상태), `features/users`(폼+다이얼로그), `features/settings`(zod 검증 폼)가 기능 추가/수정 실습에 적합합니다.

### 3.3 공용 컴포넌트 (`src/components/`)

- `ui/` — shadcn/ui 컴포넌트(버튼·다이얼로그·드롭다운 등). 일부는 RTL 지원을 위해 원본에서 **수정됨**(`scroll-area`, `sonner`, `separator`). shadcn CLI로 업데이트 시 주의가 필요합니다.
- `layout/` — `app-sidebar`, `header`, `nav-group`, `nav-user`, `team-switcher`, `top-nav` 등 관리자 셸 레이아웃.
- `data-table/` — TanStack Table 공용 래퍼(툴바·페이지네이션·열 토글).

### 3.4 상태·컨텍스트

- `context/` — `theme-provider`(라이트/다크), `font-provider`, `direction-provider`(RTL), `layout-provider`, `search-provider`(전역 커맨드 검색). 모두 `__root.tsx`에서 조립됩니다.
- `stores/` — zustand 기반 `auth-store`(토큰·사용자). **서버 상태는 TanStack Query, 클라이언트 상태는 zustand**로 분리하는 컨벤션을 그대로 보여줍니다.

### 3.5 테스트

- Vitest **브라우저 모드**(Playwright chromium) + `vitest-browser-react`로 실제 브라우저에서 컴포넌트를 렌더링해 테스트합니다.
- 단위 테스트 예시가 코드 곁에 위치합니다: `stores/auth-store.test.ts`, `context/search-provider.test.tsx`, `lib/utils.test.ts`, `hooks/use-table-url-state.test.ts` 등.
- 최초 실행 전 `pnpm test:browser:install`로 chromium을 설치해야 합니다.

## 4. 하네스·PDCA·컨벤션과의 연동

`frontend/`는 단독 실행도 가능하지만, ai-edu 하네스와 결합하면 **AI 에이전트로 계획→구현→검증** 흐름을 그대로 실습할 수 있습니다.

### 4.1 컨벤션 적용

`conventions/react-typescript/CONVENTION.md`의 규칙이 이 템플릿의 코드 스타일과 일치합니다(TS strict·`any` 금지, 함수형+훅, 한 파일 한 컴포넌트, 기능별 폴더, a11y, Prettier/ESLint). 사이트 오버레이를 생성하려면:

```bash
# frontend 레포에 react-typescript 컨벤션 overlay 생성 (common 자동 포함)
node ../harness/scripts/apply-convention.cjs ./ react-typescript
# 또는 프로파일
node ../harness/scripts/apply-convention.cjs ./ --profile react-site
```

생성물(`opencode.json` + `AGENTS.md`)이 frontend 루트에 놓이면, 해당 폴더에서 `opencode` 실행 시 **하네스 베이스 + react-typescript 팩**이 함께 적용됩니다.

### 4.2 PDCA로 기능 개발

```bash
cd frontend            # 컨벤션 overlay가 적용된 디렉터리
opencode               # 하네스 설정 자동 로드
# 에이전트 안에서:
/pdca-full add-user-export   # plan→design→do→check(품질 게이트)→iterate→report
```

품질 게이트 중 **L3 테스트·동작(≥90%, CRITICAL)** 단계에서 `e2e-runner`(Playwright MCP)와 Vitest가 활용됩니다.

### 4.3 자주 쓰는 커맨드 매핑

| 목적 | 커맨드 | frontend에서의 의미 |
|------|--------|---------------------|
| 구현 계획 | `/plan` | feature 추가 설계 |
| TDD | `/tdd` | Vitest 기준 테스트 우선 |
| 코드 리뷰 | `/code-review` | TS/React 컨벤션 점검 |
| 빌드 수정 | `/build-fix` | `tsc -b` 타입 오류 해결 |
| E2E | `/e2e` | Playwright 핵심 플로우 테스트 |
| 검증 | `/verify` | 빌드·린트·테스트·보안 일괄 |

## 5. backend/ 템플릿 (Spring Boot REST)

`backend/`는 `spring-projects/spring-boot` 공식 구조를 기준으로 구성한 **모던 Spring Boot REST API** 템플릿입니다. 프론트엔드 `features/tasks` 와 도메인을 맞춘 **작업(Task) 관리 API**를 제공하여 풀스택 실습이 가능합니다.

> `spring-projects/spring-boot` 저장소 자체는 **프레임워크 소스(수백 개 모듈)** 이지 앱 템플릿이 아니므로, 그대로 클론하지 않고 공식 구조·관례를 따르는 실행 가능한 스타터 앱으로 구성했습니다.

### 5.1 스택

| 분류 | 내용 |
|------|------|
| 런타임 | **Java 25** (Gradle toolchain) |
| 프레임워크 | **Spring Boot 4.0.6** (Spring Framework 7, Jakarta EE 11) |
| 빌드 | **Gradle** (Wrapper 포함) |
| 웹/영속성/검증 | `starter-web` + `starter-data-jpa`(H2 인메모리) + `starter-validation` |
| 직렬화 | **Jackson 3**(`tools.jackson`) — Spring Boot 4 기본 |
| 테스트 | JUnit 5 + Spring Test(MockMvc) |

### 5.2 계층 구조

```
src/main/java/com/aiedu/backend/
├─ BackendApplication.java        # 진입점
├─ task/                          # 작업 도메인
│  ├─ Task.java                   # @Entity (도메인 메서드 캡슐화)
│  ├─ TaskStatus.java / TaskPriority.java
│  ├─ TaskRepository.java         # Spring Data JPA
│  ├─ TaskService.java            # 비즈니스 로직 + 트랜잭션 경계
│  ├─ TaskController.java         # @RestController (얇게)
│  └─ dto/ TaskRequest, TaskResponse   # record + Bean Validation
└─ common/ GlobalExceptionHandler, ApiError, ResourceNotFoundException
```

설계 원칙: **컨트롤러는 얇게 / 비즈니스는 서비스 / 생성자 주입 / 엔티티 비노출(DTO 분리) / 입력은 Bean Validation, 예외는 전역 처리기**. 이 규칙은 전용 컨벤션 팩 **`spring-boot`**(`harness/conventions/spring-boot/CONVENTION.md`)에 정의되어 있습니다. (전자정부+MyBatis 사이트는 별도 `egov-backend` 팩.)

### 5.3 REST API

| 메서드 | 경로 | 설명 |
|--------|------|------|
| `GET` | `/api/tasks` · `/api/tasks/{id}` | 목록 / 단건 |
| `POST` | `/api/tasks` | 생성(201) |
| `PUT` · `DELETE` | `/api/tasks/{id}` | 수정 / 삭제(204) |

실행: `cd backend && ./gradlew bootRun` → `http://localhost:8080`. 자세한 내용은 `backend/README.md` 참조.

### 5.4 Spring Boot 4 주의점 (교육 포인트)

- **Jackson 3**: 패키지가 `com.fasterxml.jackson` → **`tools.jackson`** 으로 변경되었습니다.
- **테스트 모듈 분리**: `@AutoConfigureMockMvc` 가 `spring-boot-webmvc-test` 모듈(`org.springframework.boot.webmvc.test.autoconfigure`)로 이동 → 테스트 의존성에 추가해야 합니다.
- **버전 표기**: 실제 아티팩트는 `4.0.6`(접미사 `.RELEASE` 없음).

## 6. 검증 상태 및 운영 메모

- `frontend/`는 **shadcn-admin v2.2.1 원본을 그대로** 두되, ai-edu에 포함시키기 위해 중첩 `.git`을 제거했습니다(ai-edu 저장소가 직접 추적).

- 의존성·락파일은 **pnpm** 기준입니다. npm으로 재설치하지 마십시오(락파일 불일치).
