## 1. 개요

| 항목 | 내용 |
|------|------|
| 화면명 | 고객 관리 |
| 라우트 | `/customers` (사이드바 메뉴 "Customers" 추가) |
| 목적 | 고객사를 등록·조회·수정·삭제하는 관리 화면 |
| 사용자 | 내부 영업/운영 담당자 |
| 참조 구조 | 기존 `src/features/users` 화면과 **동일한 구조·스타일**로 구현 (목록 테이블 + 등록/수정 다이얼로그) |

## 2. 화면 구성

```
┌──────────────────────────────────────────────────────┐
│  고객 관리                              [+ 고객 등록]  │
│  ┌ 검색(고객명·담당자) ┐  ┌ 등급 필터 ▼ ┐              │
├──────────────────────────────────────────────────────┤
│  고객코드 │ 고객명 │ 등급 │ 담당자 │ 연락처 │ 가입일 │ ⋯ │
│  ───────────────────────────────────────────────────  │
│  (행 우측 ⋯ 메뉴: 수정 / 삭제)                          │
├──────────────────────────────────────────────────────┤
│                          ◀ 1 2 3 ▶  (페이지당 10건)    │
└──────────────────────────────────────────────────────┘
```

- 등록/수정은 **다이얼로그(모달)** 로 처리 — `users` 화면의 등록/수정 다이얼로그와 같은 방식.
- 삭제는 확인 다이얼로그("정말 삭제하시겠습니까?") 후 처리.

## 3. 데이터 필드 정의

| 필드 | 키 | 타입 | 필수 | 입력 UI | 검증 규칙 |
|------|-----|------|:----:|---------|----------|
| 고객코드 | `customerCode` | string | ✅ | 텍스트 (등록 시 입력, 수정 시 읽기 전용) | `C-` + 숫자 4자리 (예: `C-0001`), 중복 불가 |
| 고객명 | `name` | string | ✅ | 텍스트 | 2~30자 |
| 등급 | `grade` | enum | ✅ | 셀렉트 | `VIP` / `일반` / `휴면` (기본값: 일반) |
| 담당자 | `manager` | string | ✅ | 텍스트 | 2~20자 |
| 연락처 | `phone` | string | ✅ | 텍스트 | `010-0000-0000` 형식 |
| 이메일 | `email` | string | — | 텍스트 | 이메일 형식 (입력 시에만 검증) |
| 가입일 | `joinedAt` | date | ✅ | 데이트 피커 | 오늘 이후 날짜 불가 |
| 메모 | `note` | string | — | 텍스트영역 | 최대 200자 |

## 4. 목록 테이블 정의

| 컬럼 | 표시 | 비고 |
|------|------|------|
| 고객코드 | `C-0001` | 모노스페이스 |
| 고객명 | 텍스트 | 클릭 시 수정 다이얼로그 |
| 등급 | 배지 | VIP=보라, 일반=파랑, 휴면=회색 |
| 담당자 | 텍스트 | |
| 연락처 | 텍스트 | |
| 가입일 | `YYYY-MM-DD` | 기본 정렬: 최신순 |
| ⋯ 메뉴 | 드롭다운 | 수정 / 삭제 |

## 5. 동작 규칙

1. **등록**: [+ 고객 등록] → 다이얼로그 → 검증 통과 시 저장 → 목록 갱신 + 성공 토스트("고객이 등록되었습니다")
2. **수정**: 행 클릭 또는 ⋯ > 수정 → 같은 다이얼로그(값 채워진 상태) → 저장 시 목록 갱신 + 토스트
3. **삭제**: ⋯ > 삭제 → 확인 다이얼로그 → 확인 시 목록에서 제거 + 토스트("삭제되었습니다")
4. **검색**: 고객명·담당자 부분 일치 (입력 즉시 필터링)
5. **등급 필터**: 전체 / VIP / 일반 / 휴면
6. **페이징**: 페이지당 10건

## 6. 구현 지침 (AI에게 주는 제약)

- 백엔드 연동 없이 **목 데이터 15건**으로 동작 (`features/customers/data/`에 생성, `users` 화면의 목 데이터 방식과 동일하게)
- 기존 프로젝트의 **컴포넌트·스타일 시스템(shadcn/ui)을 그대로 사용** — 새 UI 라이브러리 추가 금지
- 파일 구조는 `src/features/users`를 본떠 `src/features/customers`로 생성, 라우트는 `src/routes/_authenticated/customers/` 추가
- 사이드바 메뉴에 "Customers" 항목 추가 (기존 메뉴 정의 방식 따름)
- 모든 표시 문구는 한국어
