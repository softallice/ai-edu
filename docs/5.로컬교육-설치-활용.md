# 로컬 교육용 OpenCode 하네스 — 설치 · 설명 · 활용

이 문서는 **개인 PC(로컬)에서 인터넷 없이도 동작하는 AI 코딩 환경**을 처음 설치하고 사용하는 방법을 단계별로 설명합니다. 수업/실습 기준이며, 서버·폐쇄망 구성은 별도 문서를 참고합니다.

- 구성: WSL + **Ollama(`qwen2.5-coder:7b`)** + **OpenCode** + **하네스(`ai-edu/harness`)**
- 선행 문서: `1.환경설정.md`(런타임 설치)
- 함께 보기: `2.PDCA-방법론.md`, `4.사이트별-컨벤션.md`

---

## 1. 이게 무엇인가요?

**OpenCode**는 터미널에서 동작하는 AI 코딩 에이전트 CLI이고, **하네스(harness)**는 그 위에 얹는 **설정 묶음**입니다. 하네스가 제공하는 것:

- **에이전트** 27종 (계획·설계·리뷰·테스트·빌드수정 등 전문 역할)
- **슬래시 커맨드** 40종 (`/plan`, `/tdd`, `/code-review`, `/pdca-full` 등)
- **PDCA 워크플로우** (계획→설계→구현→검증→개선→보고)
- **사이트별 컨벤션** 적용 체계
- **품질 훅·도구** (포맷·시크릿 점검·상태 추적 등)

```
   [내 PC]
   ┌───────────────────────────────────────────┐
   │  OpenCode (CLI)                            │
   │     └─ 하네스 설정(에이전트/커맨드/PDCA)   │
   │            │ OpenAI 호환 요청              │
   │            ▼                               │
   │  Ollama (localhost:11434)                  │
   │     └─ qwen2.5-coder:7b (로컬 모델)        │
   └───────────────────────────────────────────┘
            ※ 인터넷 불필요 (모델·도구 로컬)
```

> 로컬은 7B 경량 모델이라 가볍고 빠르지만, 아주 큰 작업에는 한계가 있습니다(8장 참고). 더 큰 모델이 필요하면 `3.폐쇄망-GPU서버-아키텍처.md`의 서버 모드로 확장합니다.

## 2. 사전 준비 (요약)

`1.환경설정.md`를 끝냈다면 아래가 준비되어 있어야 합니다.

| 항목 | 확인 명령 | 기대 |
|------|-----------|------|
| Node.js (≥18) | `node -v` | 버전 출력 |
| Ollama | `ollama --version` | 버전 출력 |
| 코딩 모델 | `ollama list` | `qwen2.5-coder:7b` 보임 |
| OpenCode | `opencode --version` | 버전 출력 |

없으면 `1.환경설정.md`의 1~4단계를 먼저 수행하세요.

## 3. 설치

### 3-1. Ollama 모델 준비
```bash
# 코딩 모델 (최초 1회 다운로드)
ollama pull qwen2.5-coder:7b

# Ollama 데몬 동작 확인 (보통 자동 실행)
curl http://localhost:11434/api/tags
```

### 3-2. OpenCode CLI 설치
```bash
npm install -g opencode-ai
opencode --version
```

### 3-3. 하네스 의존성 설치
하네스의 플러그인/도구(TypeScript)를 위해 한 번 설치합니다.
```bash
cd ai-edu/harness
npm install
```

### 3-4. 설치 확인
```bash
# 모델 응답 확인
ollama run qwen2.5-coder:7b "print hello in python"   # 확인 후 /exit

# 하네스 플러그인/도구 타입 점검 (선택)
cd ai-edu/harness && npx tsc --noEmit && echo "OK"
```

## 4. 첫 실행

하네스 디렉터리에서 OpenCode를 실행하면 `opencode.json`이 자동 로드됩니다.
```bash
cd ai-edu/harness
opencode
```

- 기본 모델: `ollama/qwen2.5-coder:7b`
- 기본 에이전트: `build` (코딩 작업용 메인)
- 종료: `Ctrl+C` 또는 `/exit`

처음 화면에서 `/help`를 입력하면 사용 가능한 커맨드를 볼 수 있습니다.

---

## 5. 기본 활용

### 5-1. 그냥 대화하며 코딩
프롬프트에 한국어/영어로 요청하면 됩니다.
```
"이 폴더에 간단한 할 일(todo) REST API를 Spring으로 만들어줘"
"이 함수 버그 찾아서 고쳐줘"
```

### 5-2. 주요 슬래시 커맨드
| 커맨드 | 용도 |
|--------|------|
| `/plan <설명>` | 구현 계획 수립(코드 작성 전 확인) |
| `/tdd <대상>` | 테스트 우선 개발(RED→GREEN→REFACTOR) |
| `/code-review` | 변경 코드 품질·보안 리뷰 |
| `/security` | 보안 점검 |
| `/build-fix` | 빌드/타입 오류 수정 |
| `/test-coverage` | 커버리지 분석 |
| `/verify` | 빌드·린트·테스트·보안 일괄 검증 |
| `/refactor-clean` | 데드코드 제거·정리 |

전체 목록은 `/help` 또는 `harness/README.md` 참고.

### 5-3. 에이전트 전환
- `Tab` 키로 기본 에이전트(`build` ↔ `pdca-orchestrator`)를 전환합니다.
- 전문 작업은 커맨드가 알맞은 서브에이전트를 자동 호출합니다(`/plan`→planner, `/code-review`→code-reviewer 등).

## 6. PDCA로 기능 개발하기

작은 기능 하나를 **계획→설계→구현→검증→개선→보고** 순서로 통제하며 만듭니다. (상세: `2.PDCA-방법론.md`)

```bash
# 전체 자동 루프
/pdca-full todo-api

# 또는 단계별로
/pdca plan todo-api      # 계획
/pdca design todo-api    # 설계
/pdca do todo-api        # 구현
/pdca check todo-api     # 품질 게이트 (L1~L4)
/pdca iterate todo-api   # 미달분 자동 수정 후 재검증
/pdca report todo-api    # 보고서

# 진행 상황
/pdca-status
/pdca-next
```

- 품질 게이트: L1 코드품질≥80 · L2 설계일치≥90% · **L3 테스트·동작≥90%(필수)** · L4 빌드·런타임≥90%
- 진행 상태는 `.pdca-status.json`에 저장되어, 대화가 길어져도 유지됩니다.

## 7. 사이트별 컨벤션 적용

수업에서 여러 스택(React-TS / Nexacro / 전자정부 백엔드)을 다룰 때, 각 실습 폴더에 맞는 규칙을 한 번에 적용합니다. (상세: `4.사이트별-컨벤션.md`)

```bash
# 실습 레포에 컨벤션 overlay 생성
node ai-edu/harness/scripts/apply-convention.cjs <실습폴더> react-typescript
node ai-edu/harness/scripts/apply-convention.cjs <실습폴더> nexacro egov-backend
# 프로파일로도 가능
node ai-edu/harness/scripts/apply-convention.cjs <실습폴더> --profile nexacro-egov
```

생성 후 그 실습 폴더에서 `opencode`를 실행하면 해당 컨벤션이 적용됩니다. (단, 모든 폴더에서 하네스 에이전트/커맨드를 쓰려면 하네스를 글로벌 베이스로 설치하는 것이 편합니다 — `4.사이트별-컨벤션.md` 2장 참고)

## 8. 자주 겪는 문제 (Troubleshooting)

| 증상 | 원인 / 해결 |
|------|-------------|
| `connection refused` / 모델 응답 없음 | Ollama 미실행 → `ollama serve` 또는 데몬 확인, `curl localhost:11434/api/tags` |
| `model not found` | `ollama pull qwen2.5-coder:7b` 재실행, `opencode.json`의 모델명 확인 |
| 커맨드가 안 보임 | `harness/` 디렉터리에서 `opencode`를 실행했는지 확인 |
| 플러그인/도구 오류 | `cd harness && npm install` 후 `npx tsc --noEmit` |
| 응답이 부정확/장황 | 7B 모델 한계 — 작업을 작게 쪼개고, PDCA 단계별 진행 + `strategic-compact` 활용 |
| 큰 작업에서 맥락 끊김 | 컨텍스트 제약 → PDCA 핸드오프 문서(`docs/pdca/`)와 `.pdca-status.json`이 상태를 보존 |
