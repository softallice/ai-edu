# 로컬 교육용 OpenCode 하네스 — 설치 · 설명 · 활용

이 문서는 **개인 PC(로컬)에서 인터넷 없이도 동작하는 AI 코딩 환경**을 처음 설치하고 사용하는 방법을 단계별로 설명합니다. 수업/실습 기준이며, 서버·폐쇄망 구성은 별도 문서를 참고합니다.

- 구성: WSL + **Ollama(`qwen2.5-coder:7b`)** + **OpenCode** + **하네스(`ai-edu/harness`)**
- 실습 대상(실제 소스): **`ai-edu/frontend`**(React-TS), **`ai-edu/backend`**(Spring Boot)
- 선행 문서: `1.환경설정.md`(런타임 설치)
- 함께 보기: `2.PDCA-방법론.md`, `4.사이트별-컨벤션.md`, `6.프론트엔드-템플릿-구조.md`

---

## 1. 이게 무엇인가요?

**OpenCode**는 터미널에서 동작하는 AI 코딩 에이전트 CLI이고, **하네스(harness)**는 그 위에 얹는 **설정 묶음**입니다. 하네스가 제공하는 것:

- **에이전트** 27종 (계획·설계·리뷰·테스트·빌드수정 등 전문 역할)
- **슬래시 커맨드** 40종 (`/plan`, `/tdd`, `/code-review`, `/pdca-full` 등)
- **PDCA 워크플로우** (계획→설계→구현→검증→개선→보고)
- **사이트별 컨벤션** 적용 체계 (common · react-typescript · spring-boot · nexacro · egov-backend)
- **품질 훅·도구** (포맷·시크릿 점검·상태 추적 등)

```
   [내 PC]
   ┌───────────────────────────────────────────┐
   │  OpenCode (CLI)                            │
   │     └─ 하네스 설정(에이전트/커맨드/PDCA)   │
   │            │ OpenAI 호환 요청              │
   │            ▼                               │
   │  Ollama (localhost:11434)                  │
   │     └─ qwen2.5-coder:7b (로컬 모델)        │
   └───────────────────────────────────────────┘
            ※ 인터넷 불필요 (모델·도구 로컬)
```

> 로컬은 경량 모델이라 가볍고 빠르지만, 아주 큰 작업에는 한계가 있습니다(8장 참고). 기본은 7B이며 **CPU 전용/저사양이면 3B로 낮추면 더 빠릅니다**(3-1 참고). 더 큰 모델이 필요하면 `3.폐쇄망-GPU서버-아키텍처.md`의 서버 모드로 확장합니다.
> Claude Code로 동일 워크플로우를 쓰고 싶다면 자매 하네스 `ai-edu/harness-claude-code`를 참고하세요(클라우드 Claude 모델, 티어링).

## 3. 설치

### 3-1. Ollama 모델 준비

스펙에 맞는 코딩 모델을 받습니다. **GPU 없이 CPU로만 돌리는 노트북(예: NPU만 있는 기기 — NPU는 Ollama가 못 씀)이면 가벼운 `3b`를 권장**합니다(속도↑, 품질 약간↓).

```bash
# 경량: 3B — CPU 전용/저사양 권장 (더 빠름)
ollama pull qwen2.5-coder:3b
# 표준: 7B — GPU/여유 있는 환경
ollama pull qwen2.5-coder:7b

# Ollama 데몬 동작 확인 (보통 자동 실행)
curl http://localhost:11434/api/tags
```

#### 모델 바꾸기 (7b ↔ 3b)
하네스 기본 모델은 `7b`입니다. `3b`로 바꾸려면 하네스 설정의 모델 참조를 한 번에 교체합니다(에이전트별 설정 포함).
```bash
cd ~/work/ai-edu/harness
cp opencode.json opencode.json.bak                  # 백업
sed -i 's/qwen2.5-coder:7b/qwen2.5-coder:3b/g' opencode.json
grep -c 'qwen2.5-coder:3b' opencode.json            # 교체 개수 확인(0이면 실패)
```
되돌리려면 위에서 `3b`↔`7b`를 바꿔 다시 실행하거나 `opencode.json.bak`을 복원합니다.
> 참고: 글로벌 베이스로 링크(4-2)했다면 `~/.config/opencode/opencode.json`이 곧 이 파일이라 함께 반영됩니다.

### 3-2. OpenCode CLI 설치
```bash
npm install -g opencode-ai
opencode --version
```

### 3-3. 하네스 의존성 설치
하네스의 플러그인/도구(TypeScript)를 위해 한 번 설치합니다.
```bash
cd ~/work/ai-edu/harness
npm install
```

### 3-4. 설치 확인
```bash
# 모델 응답 확인 (한국어로 물어도 됩니다)
ollama run qwen2.5-coder:7b "파이썬으로 hello 출력"   # 확인 후 /exit

# 하네스 플러그인/도구 타입 점검 (선택)
cd ~/work/ai-edu/harness && npx tsc --noEmit && echo "OK"
```

> 실습 템플릿(`frontend`/`backend`)은 각자 별도 의존성 설치가 필요합니다(프론트 `pnpm install`, 백엔드 `./gradlew build`). 자세한 내용은 각 폴더의 `README.md`와 `6.프론트엔드-템플릿-구조.md` 참고.

## 4. 첫 실행

> ⚠️ **핵심: OpenCode는 "실행한 폴더(cwd)"를 작업 디렉터리로 삼습니다.** 그래서 실행 위치가 곧 코드가 생성/수정되는 위치입니다.

### 4-1. 하네스 체험 (cwd = harness)
커맨드를 처음 익히거나 일회성 연습용. 만든 파일은 `harness/` 안에 생깁니다.
```bash
cd ~/work/ai-edu/harness
opencode
```

- 기본 모델: `ollama/qwen2.5-coder:7b`
- 기본 에이전트: `build` (코딩 작업용 메인)
- 종료: `Ctrl+C` 또는 `/exit`. `/help`로 커맨드 목록 확인.

### 4-2. 실제 프로젝트 개발 (cwd = frontend/backend) — 권장
실제 소스는 `frontend/`·`backend/`에 있습니다. **그 폴더에서 실행**해야 코드가 올바른 위치에 생성됩니다.
에이전트·커맨드·PDCA는 하네스에만 정의되어 있으므로, **하네스를 글로벌 베이스로 설치**하고 각 프로젝트에 **컨벤션 overlay**를 적용합니다.

```bash
# 1) 하네스를 글로벌 베이스로 링크 (모든 폴더에서 에이전트/커맨드/PDCA 동작)
#    ⚠️ ~/.config/opencode 가 이미 있으면 ln 이 그 안에 중첩(~/.config/opencode/harness)되어
#       글로벌 설정으로 인식되지 않습니다. 먼저 백업 후 교체하세요.
[ -e ~/.config/opencode ] && mv ~/.config/opencode ~/.config/opencode.bak
ln -s ~/work/ai-edu/harness ~/.config/opencode

#    확인: 아래가 harness/opencode.json 을 가리켜야 함(agent/command 수가 보임)
node -e "const j=require(process.env.HOME+'/.config/opencode/opencode.json');console.log('agents',Object.keys(j.agent).length,'commands',Object.keys(j.command).length)"

# 2) 소스 폴더에 컨벤션 overlay 생성 (최초 1회)
node ~/.config/opencode/scripts/apply-convention.cjs ~/work/ai-edu/frontend react-typescript
node ~/.config/opencode/scripts/apply-convention.cjs ~/work/ai-edu/backend  spring-boot

# 3) 소스 폴더에서 실행
cd ~/work/ai-edu/frontend && opencode      # 또는  cd ~/work/ai-edu/backend && opencode
```

- OpenCode가 글로벌 베이스(`~/.config/opencode/`) + cwd의 overlay(`opencode.json`)를 **머지**합니다.
- overlay는 **컨벤션 instructions만** 추가하고, 에이전트·커맨드는 **글로벌 베이스(하네스)** 에서 옵니다. 그래서 두 가지가 모두 필요합니다.
- 글로벌 링크가 번거로우면, overlay 생성만은 하네스 실제 경로로도 됩니다: `node ~/work/ai-edu/harness/scripts/apply-convention.cjs <폴더> <팩>`.
- 배치 모델 상세: `4.사이트별-컨벤션.md` 2장.

## 5. 기본 활용

### 5-1. 그냥 대화하며 코딩
프롬프트에 **한국어 또는 영어**로 요청하면 됩니다(모델이 한국어를 이해·응답합니다).
```
"이 폴더에 간단한 할 일(todo) REST API를 Spring으로 만들어줘"
"이 함수 버그 찾아서 고쳐줘"
```

> 7B 모델 + 영어 시스템 프롬프트라, 서브에이전트 작업 중에는 응답이 **영어로 나오거나 한·영이 섞일 수** 있습니다. 한국어 응답을 고정하려면 "한국어로 답해줘"를 덧붙이거나 하네스 지침에 한 줄 추가하세요. 코드(식별자·주석)는 영어가 무난합니다.

### 5-2. 주요 슬래시 커맨드
| 커맨드 | 용도 |
|--------|------|
| `/plan <설명>` | 구현 계획 수립(코드 작성 전 확인) |
| `/tdd <대상>` | 테스트 우선 개발(RED→GREEN→REFACTOR) |
| `/code-review` | 변경 코드 품질·보안 리뷰 |
| `/security` | 보안 점검 |
| `/build-fix` | 빌드/타입 오류 수정 |
| `/test-coverage` | 커버리지 분석 |
| `/verify` | 빌드·린트·테스트·보안 일괄 검증 |
| `/refactor-clean` | 데드코드 제거·정리 |
| `/apply-convention <폴더> <팩>` | 실습 폴더에 컨벤션 overlay 적용 |

전체 목록은 `/help` 또는 `harness/README.md` 참고.

### 5-3. 에이전트 전환
- `Tab` 키로 기본(primary) 에이전트(`build` ↔ `pdca-orchestrator`)를 전환합니다.
- `build`가 일반 코딩을 직접 수행하고, 전문 작업은 커맨드가 알맞은 **서브에이전트**를 자동 호출합니다(`/plan`→planner, `/code-review`→code-reviewer 등).

## 6. PDCA로 기능 개발하기

작은 기능 하나를 **계획→설계→구현→검증→개선→보고** 순서로 통제하며 만듭니다. (상세: `2.PDCA-방법론.md`)

```bash
# 전체 자동 루프
/pdca-full todo-api

# 또는 단계별로
/pdca plan todo-api      # 계획
/pdca design todo-api    # 설계
/pdca do todo-api        # 구현
/pdca check todo-api     # 품질 게이트 (L1~L4)
/pdca iterate todo-api   # 미달분 자동 수정 후 재검증
/pdca report todo-api    # 보고서

# 진행 상황
/pdca-status
/pdca-next
```

- 품질 게이트: L1 코드품질≥80 · L2 설계일치≥90% · **L3 테스트·동작≥90%(필수)** · L4 빌드·런타임≥90%
- 진행 상태는 `.pdca-status.json`에 저장되어, 대화가 길어져도 유지됩니다.

## 7. 사이트별 컨벤션 적용

수업에서 여러 스택을 다룰 때, 각 실습 폴더에 맞는 규칙을 한 번에 적용합니다. (상세: `4.사이트별-컨벤션.md`)

**컨벤션 팩 5종** — `common`(항상 포함) · `react-typescript` · `spring-boot` · `nexacro` · `egov-backend`
**프로파일** — `react-site` · `spring-boot` · `react-spring`(풀스택) · `nexacro-egov` · `egov-only`

```bash
# 팩 직접 지정 (common 자동 포함)
node ~/.config/opencode/scripts/apply-convention.cjs ~/work/ai-edu/frontend react-typescript
node ~/.config/opencode/scripts/apply-convention.cjs ~/work/ai-edu/backend  spring-boot
node ~/.config/opencode/scripts/apply-convention.cjs <실습폴더> nexacro egov-backend

# 프로파일로 지정
node ~/.config/opencode/scripts/apply-convention.cjs <실습폴더> --profile react-spring
```

생성물: 실습 폴더에 `opencode.json`(팩 instructions) + `AGENTS.md`(요약). 이후 그 폴더에서 `opencode`를 실행하면 컨벤션이 적용됩니다.

> 글로벌 링크(4-2)를 안 했다면 `~/.config/opencode/scripts/...` 대신 하네스 실제 경로 `~/work/ai-edu/harness/scripts/apply-convention.cjs`로 실행하세요. 단, 에이전트·커맨드까지 모든 폴더에서 쓰려면 글로벌 베이스 설치가 필요합니다(4-2).

## 8. 자주 겪는 문제 (Troubleshooting)

| 증상 | 원인 / 해결 |
|------|-------------|
| `connection refused` / 모델 응답 없음 | Ollama 미실행 → `ollama serve` 또는 데몬 확인, `curl localhost:11434/api/tags` |
| `model not found` | `ollama pull qwen2.5-coder:7b` 재실행, `opencode.json`의 모델명 확인 |
| 커맨드가 안 보임 | `harness/`에서 실행했는지, 또는 하네스를 글로벌 베이스(`~/.config/opencode/`)로 링크했는지 확인(4-2) |
| `apply-convention.cjs` `Cannot find module .../.config/opencode/scripts/...` | `~/.config/opencode`가 이미 있어 `ln`이 중첩됨. 4-2대로 **백업 후 교체**하거나, 하네스 실제 경로로 실행: `node ~/work/ai-edu/harness/scripts/apply-convention.cjs <폴더> <팩>` |
| `opencode` 시작 시 `ConfigInvalidError` / `Configuration is invalid ... Unrecognized key: $comment` | OpenCode 최신 버전은 overlay `opencode.json`의 비표준 키(`$comment`)를 거부함. 해당 폴더에서 overlay를 **재생성**: `node ~/.config/opencode/scripts/apply-convention.cjs <폴더> <팩> --force` (또는 overlay에서 `$comment` 줄 삭제) |
| 코드가 엉뚱한 폴더에 생김 | OpenCode는 cwd가 작업 폴더 — frontend/backend 코드는 **그 폴더에서** `opencode` 실행(4-2) |
| 플러그인/도구 오류 | `cd harness && npm install` 후 `npx tsc --noEmit` |
| 응답이 너무 느림 | GPU 미사용(CPU/NPU 노트북)에서 7B는 느립니다 — 3-1의 방법으로 `qwen2.5-coder:3b`로 교체. NPU는 Ollama가 사용하지 못합니다. 사양 가이드: `7.로컬-실행-하드웨어-사양.md` |
| 툴 호출이 텍스트(JSON)로만 나오고 파일이 안 바뀜 | 소형 로컬 모델의 tool-calling 한계 — 실제 편집 자동화는 32B급(24GB VRAM)+ 또는 `harness-claude-code`(클라우드 Claude) 권장. 상세: `7.로컬-실행-하드웨어-사양.md` |
| 응답이 부정확/장황 | 모델 한계 — 작업을 작게 쪼개고, PDCA 단계별 진행 + `strategic-compact` 활용. (3B는 7B보다 품질이 더 낮을 수 있음) |
| 큰 작업에서 맥락 끊김 | 컨텍스트 제약 → PDCA 핸드오프 문서(`docs/pdca/`)와 `.pdca-status.json`이 상태를 보존 |

## 부록 A. 빠른 시작 한 장 요약

**(A) 하네스 체험** — 커맨드 익히기 (cwd=harness)
```bash
ollama pull qwen2.5-coder:3b      # CPU 전용/저사양. 여유되면 :7b
npm install -g opencode-ai
cd ~/work/ai-edu/harness && npm install
# (선택) 3B로 낮추기:  sed -i 's/qwen2.5-coder:7b/qwen2.5-coder:3b/g' opencode.json
opencode
# 실행 후:  /pdca-full my-first-feature   (파일은 harness/ 안에 생성)
```

**(B) 실제 개발** — frontend/backend 코드 작업 (권장)
```bash
# 글로벌 베이스 1회 설정
[ -e ~/.config/opencode ] && mv ~/.config/opencode ~/.config/opencode.bak
ln -s ~/work/ai-edu/harness ~/.config/opencode
# 컨벤션 overlay 1회 생성
node ~/.config/opencode/scripts/apply-convention.cjs ~/work/ai-edu/frontend react-typescript
node ~/.config/opencode/scripts/apply-convention.cjs ~/work/ai-edu/backend  spring-boot
# 소스 폴더에서 작업
cd ~/work/ai-edu/frontend && opencode      # 또는  cd ~/work/ai-edu/backend && opencode
```
