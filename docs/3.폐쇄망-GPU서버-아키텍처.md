# 폐쇄망 GPU 서버 + 로컬 에이전트 아키텍처

이 문서는 **인터넷이 전무한 완전 폐쇄망(air-gapped)** 환경에서, GPU가 많은 **중앙 서버에 대형 모델을 vLLM으로 서빙**하고, 각 개발자의 **로컬 PC에서 OpenCode 하네스가 서버와 통신**하며 개발하는 아키텍처를 정리합니다. 코드 생성뿐 아니라 **이미지(Vision)·글쓰기(Writing)** 활용까지 포함합니다.

- 서빙 엔진: **vLLM** (고처리량, OpenAI 호환 API, 멀티 GPU 텐서 병렬)
- 격리 수준: **완전 오프라인** (모델·패키지·MCP 전부 사전 반입)
- 관련 산출물: 서버 모드 설정 예시 `harness/config/opencode.server.example.json`

---

## 1. 아키텍처 개요

```
                        폐쇄망 (인터넷 없음)
┌──────────────────────────────────────────────────────────────────────┐
│                                                                        │
│   [개발자 PC #1]            [개발자 PC #2]          [개발자 PC #N]      │
│   OpenCode 하네스           OpenCode 하네스          OpenCode 하네스    │
│   (thin client)             (thin client)            (thin client)     │
│        │                         │                        │            │
│        └──────────────┬──────────┴───────────┬───────────┘            │
│                       │  OpenAI 호환 HTTP(S)  │  (사내 LAN)            │
│                       ▼                       ▼                        │
│         ┌──────────────────────────────────────────────┐              │
│         │             GPU 서버 (멀티 GPU)               │              │
│         │  ┌────────────────────────────────────────┐  │              │
│         │  │ (선택) LiteLLM 게이트웨이  :4000       │  │              │
│         │  └───────┬────────────┬────────────┬──────┘  │              │
│         │          ▼            ▼            ▼          │              │
│         │   vLLM :8001    vLLM :8002    vLLM :8003      │              │
│         │   Code 32/72B   Vision VL     Writing 72B     │              │
│         │   (TP×GPUs)     (GPU n)       (TP×GPUs)       │              │
│         │                                                │             │
│         │   /models (사전 반입된 HF 가중치)             │              │
│         └──────────────────────────────────────────────┘              │
└──────────────────────────────────────────────────────────────────────┘
```

**역할 분담**

| 구성요소 | 역할 |
|----------|------|
| GPU 서버 | vLLM으로 대형 코드/비전/글쓰기 모델을 상시 서빙 (OpenAI 호환 `/v1`) |
| 로컬 PC | OpenCode 하네스 실행. 모델 추론은 전량 서버에 위임(thin client). 서버 장애 시 로컬 Ollama 폴백 |
| (선택) LiteLLM | 여러 vLLM 인스턴스를 단일 엔드포인트·모델명으로 통합, 키/로드밸런싱 관리 |

## 2. GPU 서버 — vLLM 서빙

### 2.1 모델 라인업 (GPU 티어별)

전부 **오픈웨이트(Qwen2.5 계열)** 라 폐쇄망 반입이 자유롭습니다. 코드/비전/글쓰기 3축으로 구성합니다.

| GPU 티어 | 코드 모델 | 비전 모델 | 글쓰기/범용 모델 | 비고 |
|----------|-----------|-----------|------------------|------|
| **24GB×N** (4090/3090) | Qwen2.5-Coder-32B-Instruct **AWQ/GPTQ 4bit** (1~2장) | Qwen2.5-VL-7B-Instruct | Qwen2.5-14B/32B-Instruct (4bit) | 양자화로 VRAM 절약, TP=2 권장 |
| **48~80GB×N** (A6000/A100/H100) | Qwen2.5-Coder-32B (fp16, 1~2장) 또는 **Coder-72B** (TP) | Qwen2.5-VL-32B/72B | Qwen2.5-72B-Instruct (TP) | 다수 동시 사용자에 적합 |
| **소수 고성능** (1~2× H100/A100 80GB) | Qwen2.5-Coder-32B fp16 (1장) | Qwen2.5-VL-7B (잔여 VRAM/시분할) | Qwen2.5-32B-Instruct | 단일 대형 모델 안정 운영 우선 |

> 권장 기본값: **코드=Qwen2.5-Coder-32B**, **비전=Qwen2.5-VL-7B**, **글쓰기=Qwen2.5-72B-Instruct**.
> VRAM이 빠듯하면 글쓰기를 코드 모델과 공유(32B)하고 비전만 별도 인스턴스로 둡니다.

### 2.2 vLLM 인스턴스 실행

모델 1개당 vLLM 프로세스 1개를 서로 다른 포트/GPU에 띄웁니다. 대형 모델은 텐서 병렬(`--tensor-parallel-size`)로 여러 GPU에 분산합니다.

```bash
# 공통: 완전 오프라인 강제 (외부 다운로드 시도 차단)
export HF_HUB_OFFLINE=1
export TRANSFORMERS_OFFLINE=1
export VLLM_API_KEY="<사내 공유 키>"     # 인증 토큰

# (1) 코드 모델 — GPU 0,1 텐서 병렬, 포트 8001
CUDA_VISIBLE_DEVICES=0,1 \
vllm serve /models/Qwen2.5-Coder-32B-Instruct \
  --served-model-name qwen2.5-coder-32b \
  --tensor-parallel-size 2 \
  --api-key "$VLLM_API_KEY" \
  --host 0.0.0.0 --port 8001 \
  --max-model-len 32768 --gpu-memory-utilization 0.92

# (2) 비전 모델 — GPU 2, 포트 8002 (멀티모달)
CUDA_VISIBLE_DEVICES=2 \
vllm serve /models/Qwen2.5-VL-7B-Instruct \
  --served-model-name qwen2.5-vl-7b \
  --api-key "$VLLM_API_KEY" \
  --host 0.0.0.0 --port 8002 \
  --max-model-len 16384

# (3) 글쓰기 모델 — GPU 3,4,5,6 텐서 병렬, 포트 8003
CUDA_VISIBLE_DEVICES=3,4,5,6 \
vllm serve /models/Qwen2.5-72B-Instruct \
  --served-model-name qwen2.5-72b-instruct \
  --tensor-parallel-size 4 \
  --api-key "$VLLM_API_KEY" \
  --host 0.0.0.0 --port 8003 \
  --max-model-len 32768 --gpu-memory-utilization 0.92
```

각 인스턴스는 OpenAI 호환 엔드포인트를 제공합니다:
`http://SERVER_IP:8001/v1/chat/completions` 등. systemd 서비스로 등록해 부팅 시 자동 기동을 권장합니다.

### 2.3 다중 모델 노출 — 두 가지 방식

**방식 A (단순·권장): 로컬 설정에서 다중 provider 직결**
게이트웨이 없이 OpenCode가 포트별 vLLM에 직접 접속합니다. 구성요소가 적어 폐쇄망에 유리합니다. → 4장 참조.

**방식 B (확장): LiteLLM 게이트웨이로 단일 엔드포인트 통합**
사용자가 많거나 라우팅/쿼터/로드밸런싱이 필요하면 LiteLLM 프록시를 둡니다.

```yaml
# /etc/litellm/config.yaml
model_list:
  - model_name: code
    litellm_params: { model: openai/qwen2.5-coder-32b, api_base: http://localhost:8001/v1, api_key: os.environ/VLLM_API_KEY }
  - model_name: vision
    litellm_params: { model: openai/qwen2.5-vl-7b,    api_base: http://localhost:8002/v1, api_key: os.environ/VLLM_API_KEY }
  - model_name: writing
    litellm_params: { model: openai/qwen2.5-72b-instruct, api_base: http://localhost:8003/v1, api_key: os.environ/VLLM_API_KEY }
```
```bash
litellm --config /etc/litellm/config.yaml --port 4000   # → http://SERVER_IP:4000/v1 (모델명: code/vision/writing)
```

### 2.4 통신·보안

- **바인드/방화벽**: vLLM/게이트웨이를 `0.0.0.0`로 띄우되 방화벽에서 사내 개발 서브넷만 허용합니다.
- **인증**: vLLM `--api-key`로 토큰 강제. 로컬은 `VLLM_API_KEY` 환경변수로 주입(설정 파일에 평문 저장 금지).
- **TLS(선택)**: nginx 리버스 프록시 + 사내 CA 인증서로 `https://`. 폐쇄망이라 평문 HTTP도 가능하나, 멀티 테넌트면 TLS 권장.
- **헬스체크**: `curl http://SERVER_IP:8001/v1/models` (헤더 `Authorization: Bearer $VLLM_API_KEY`).

## 3. 로컬 에이전트 — OpenCode 하네스 연동

### 3.1 서버 모드 설정 적용

`harness/config/opencode.server.example.json`의 `provider` / `model` / `small_model` / `agent.*.model` 키를 `harness/opencode.json`에 병합합니다. `SERVER_IP`만 실제 주소로 바꾸고, 키는 환경변수로 주입합니다.

```bash
export VLLM_API_KEY="<사내 공유 키>"
cd harness && opencode
```

핵심 provider 블록(방식 A, 직결):
```jsonc
"model": "vllm-code/qwen2.5-coder-32b",
"small_model": "vllm-code/qwen2.5-coder-7b",
"provider": {
  "vllm-code":    { "npm": "@ai-sdk/openai-compatible", "options": { "baseURL": "http://SERVER_IP:8001/v1", "apiKey": "{env:VLLM_API_KEY}" }, "models": { "qwen2.5-coder-32b": {}, "qwen2.5-coder-7b": {} } },
  "vllm-vision":  { "npm": "@ai-sdk/openai-compatible", "options": { "baseURL": "http://SERVER_IP:8002/v1", "apiKey": "{env:VLLM_API_KEY}" }, "models": { "qwen2.5-vl-7b": {} } },
  "vllm-writing": { "npm": "@ai-sdk/openai-compatible", "options": { "baseURL": "http://SERVER_IP:8003/v1", "apiKey": "{env:VLLM_API_KEY}" }, "models": { "qwen2.5-72b-instruct": {} } }
}
```
> 방식 B(게이트웨이)면 provider 1개(`vllm`)만 두고 `baseURL: http://SERVER_IP:4000/v1`, 모델명 `code/vision/writing`을 사용합니다.

### 3.2 에이전트별 모델 라우팅

작업 성격에 맞춰 에이전트마다 서버 모델을 지정합니다. (예시는 server.example.json에 포함)

| 에이전트 | 모델 | 이유 |
|----------|------|------|
| build, planner, architect, code-reviewer, security-reviewer, tdd-guide, pdca-orchestrator | `vllm-code/qwen2.5-coder-32b` | 코드 이해·생성·리뷰 |
| doc-updater (+PDCA report 단계) | `vllm-writing/qwen2.5-72b-instruct` | 보고서·문서 품질 |
| (신규) screen-analyzer 등 이미지 작업 | `vllm-vision/qwen2.5-vl-7b` | 멀티모달 입력 |
| small_model (요약/제목 등 경량) | `vllm-code/qwen2.5-coder-7b` | 비용·지연 절감 |

이로써 1·2번 문서의 **단일 로컬 7B → 서버 멀티 모델 라우팅**으로 전환되며, PDCA의 단계별 라우팅 개념(2번 문서 8장)이 실제 모델 다양성으로 복원됩니다.

### 3.3 서버 장애 시 로컬 Ollama 폴백

서버 점검·네트워크 단절 대비로 로컬 PC에 경량 모델(`qwen2.5-coder:7b`)을 유지합니다(1번 문서 구성). `opencode.json`에 `ollama` provider를 함께 두고, 서버 불가 시 모델을 `ollama/qwen2.5-coder:7b`로 전환하면 오프라인으로도 작업이 지속됩니다.

## 4. 이미지(Vision) 활용

비전 모델(Qwen2.5-VL)로 **화면 캡처·설계 이미지·다이어그램**을 입력해 분석·코드화합니다.

- OpenCode는 멀티모달 모델에 이미지 입력을 전달할 수 있습니다. 비전 작업은 `vllm-vision/qwen2.5-vl-7b`를 사용하는 에이전트/세션에서 수행합니다.
- 활용 예: UI 스크린샷 → 컴포넌트/레이아웃 분석 → React/화면 코드 초안, 디자인 시안 → 마크업 프로토타입, 오류 스크린샷 판독.
- 권장: 이미지 전용 에이전트를 추가하고 `model: vllm-vision/qwen2.5-vl-7b`로 지정. 분석 결과(텍스트/좌표/매핑)를 코드 에이전트로 핸드오프하면 7B 비전 + 32B 코드의 장점을 결합할 수 있습니다.

```jsonc
// opencode.json agent 추가 예시
"screen-analyzer": {
  "description": "스크린샷/설계 이미지 분석 후 컴포넌트·레이아웃·코드 매핑 산출",
  "mode": "subagent",
  "model": "vllm-vision/qwen2.5-vl-7b",
  "tools": { "read": true, "bash": true, "write": false, "edit": false }
}
```

## 5. 글쓰기(Writing) 활용

대형 범용 모델(Qwen2.5-72B-Instruct)로 **문서·보고서·릴리스 노트·블로그/아티클**을 생성합니다.

- PDCA `report` 단계와 `doc-updater` 에이전트를 `vllm-writing`으로 라우팅하면 보고서 품질이 향상됩니다.
- 장문 작성·요약·번역·기술 문서화에 활용. 코드 모델보다 서술·구성 능력이 우수합니다.
- ECC/하네스의 작문 스킬(예: `frontend-slides`, 필요 시 `article-writing` 등)을 글쓰기 모델 세션에서 사용합니다.
- 산출물 말투 규칙: 사내 블로그/티스토리용 글은 경어체(~입니다/~합니다체)로 작성합니다.

## 6. 완전 오프라인 프로비저닝

인터넷이 전무하므로, **인터넷 가능 머신에서 받아 매체(USB/내부 전송)로 반입**합니다.

### 6.1 모델 가중치 반입 (vLLM = HF 포맷)
```bash
# [인터넷 머신] HF 스냅샷 다운로드
huggingface-cli download Qwen/Qwen2.5-Coder-32B-Instruct --local-dir Qwen2.5-Coder-32B-Instruct
huggingface-cli download Qwen/Qwen2.5-VL-7B-Instruct     --local-dir Qwen2.5-VL-7B-Instruct
huggingface-cli download Qwen/Qwen2.5-72B-Instruct        --local-dir Qwen2.5-72B-Instruct
tar czf models.tar.gz Qwen2.5-*            # 매체로 반입

# [폐쇄망 서버] 전개 후 오프라인 강제
tar xzf models.tar.gz -C /models
export HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1
```

### 6.2 vLLM / Python 런타임 오프라인
```bash
# [인터넷 머신] 휠 사전 수집
pip download vllm -d wheelhouse/           # 의존성 포함
# [폐쇄망] 오프라인 설치
pip install --no-index --find-links wheelhouse/ vllm
```
> CUDA/드라이버는 서버에 사전 설치. vLLM은 GPU 아키텍처에 맞는 빌드를 반입합니다.

### 6.3 Node / OpenCode / 하네스 오프라인
```bash
# [인터넷 머신] OpenCode CLI 패키징
npm pack opencode-ai          # → opencode-ai-<ver>.tgz (매체 반입)
# 하네스 의존성 번들: harness/node_modules 통째로 tar (이미 설치되어 있음)
tar czf harness-node_modules.tar.gz harness/node_modules

# [폐쇄망 PC]
npm install -g ./opencode-ai-<ver>.tgz     # 전역 설치(오프라인)
tar xzf harness-node_modules.tar.gz        # harness/ 아래로 전개
```
> Node.js 자체도 오프라인 인스톨러(nvm 캐시 또는 배포판 tar)로 반입합니다.

### 6.4 MCP 서버 오프라인 처리
완전 오프라인에서는 `npx`가 패키지를 받지 못하므로 다음과 같이 처리합니다.

| MCP | 폐쇄망 처리 |
|-----|-------------|
| `exa`, `github`, `context7` | **비활성화** (외부 네트워크/원격 의존) — `enabled:false` 유지 |
| `memory`, `sequential-thinking` | npm 패키지를 사전 설치(전역) 후 `command`를 `npx -y` 대신 로컬 경로로 지정, 또는 비활성화 |
| `playwright` | 브라우저 바이너리까지 사전 반입한 경우에만 활성화, 아니면 비활성화 |

> 현재 `harness/opencode.json`은 `github`/`exa`가 이미 `enabled:false`입니다. 완전 오프라인에서는 `context7`도 `false`로 두고, 나머지는 사전 설치 여부에 맞춰 조정합니다.

- [ ] 서버 차단 시 `ollama/qwen2.5-coder:7b` 폴백 동작

## 8. 운영 팁

- **동시성**: vLLM은 연속 배칭으로 다수 요청을 처리합니다. 사용자 증가 시 코드 모델 인스턴스를 수평 확장하고 LiteLLM으로 로드밸런싱합니다.
- **컨텍스트**: 32B/72B는 7B보다 컨텍스트 여유가 크지만, 대규모 작업에는 여전히 `strategic-compact` 스킬과 PDCA 단계 핸드오프(2번 문서)를 병행합니다.
- **모델 갱신**: 신모델은 인터넷 머신에서 받아 동일 절차로 반입 후 vLLM `--served-model-name`만 맞추면 로컬 설정 변경 없이 교체됩니다.
- **보안**: 키는 환경변수로만 주입하고 설정 파일·로그에 남기지 않습니다(하네스 보안 규칙 준수).
