# 로컬 실행 하드웨어 사양 가이드

이 문서는 **로컬에서 AI 코딩 하네스(OpenCode + 로컬 모델)를 어느 정도 사양에서 돌릴 수 있는지** 정리합니다. "체험·학습"과 "실제 코드 자동 편집"은 요구 사양이 크게 다릅니다.

> 배경: 작은 로컬 모델(예: `qwen2.5-coder:7b`)은 CPU에서 느릴 뿐 아니라, **툴 호출(파일 읽기/수정 실행)이 불안정**합니다. 실제로 7B에 `write` 툴을 줘도 구조화된 `tool_calls` 대신 JSON을 텍스트로 흘려, 파일이 실제로 수정되지 않는 경우가 많습니다. 자세한 원인은 8장(=`5.로컬교육-설치-활용.md` 트러블슈팅) 참고.

---

## 1. 두 가지 핵심 원칙

1. **속도 = GPU VRAM(또는 Apple 통합 메모리) 용량.** 모델이 VRAM에 통째로 올라가야 빠릅니다. CPU 전용은 느립니다.
2. **툴 호출/에이전트 신뢰도 = 모델 크기·품질.** 하드웨어가 아니라 모델이 좌우합니다. 대략 **14B부터 쓸만해지고, 32B가 로컬 현실 스위트스폿**입니다(7B는 학습용).

➡ 그래서 "더 큰 모델 + 그 모델을 담을 VRAM" **둘 다** 필요합니다.

**모델 크기 → 대략 VRAM(Q4 양자화 기준, 컨텍스트 별도 +α)**

| 모델 | 파라미터 | VRAM(Q4) |
|------|----------|----------|
| 7B | 7.6B | ≈ 5 GB |
| 14B | 14B | ≈ 9–10 GB |
| 32B | 32B | ≈ 20–22 GB |
| 70B | 70B | ≈ 40–48 GB |

---

## 2. 등급별 현실 사양

| 등급 | 용도 | 권장 모델 | 필요 VRAM/메모리 | 예시 하드웨어 |
|------|------|-----------|------------------|---------------|
| **체험/학습** | 워크플로우(PDCA·커맨드·컨벤션) 익히기 | 7B (또는 3B) | NVIDIA **8–12GB** / Mac 16–24GB | RTX 3060 12G·4060 / M-series 16~24G — **빠르지만 tool-call 신뢰도는 낮음** |
| **현실 최소** | 실제 편집이 가끔 성공 | 14B | NVIDIA **16GB** / Mac 32–36GB | RTX 4070 Ti SUPER 16G·4060 Ti 16G |
| **권장(스위트스폿)** | 안정적 로컬 에이전트 | **32B** | NVIDIA **24GB** / Mac 48–64GB | **RTX 3090·4090(24G)** / Mac Studio·MBP 64G |
| **고급** | 70B급 | 70B | 48GB+ / Mac 64–128GB | 2×24G, A6000·RTX 6000 Ada / M Ultra |

공통 권장: 시스템 RAM **32–64GB**, NVMe SSD. CPU 자체는 큰 변수가 아닙니다(연산은 GPU가 담당).

---

## 3. WSL + Intel 환경 주의 (현재 교육 노트북 기준)

- WSL2에서 GPU 가속은 **NVIDIA(CUDA)만** 사실상 매끄럽습니다. AMD/Intel GPU는 까다롭고, **NPU는 Ollama가 사용하지 못합니다.**
- 따라서 얇은 Intel/NPU 노트북(예: Core Ultra 시리즈)은 **대용량 GPU 장착 경로가 없어** 로컬 대형 모델 구동에 부적합합니다 → 아래 3가지 길 중 선택.

---

## 4. 현실적인 선택지 3가지

1. **NVIDIA GPU 데스크탑/박스** — RTX 3090(중고 가성비)·4090 **24GB**로 **Qwen2.5-Coder-32B**. 로컬 에이전트가 "쓸만"해지는 최소선.
2. **Apple Silicon** — M3/M4 Pro·Max, 통합 메모리 **48–64GB**. Ollama가 Metal을 지원하므로(NPU와 달리) 14B–32B가 잘 돌고 드라이버 삽질이 없습니다. "한 대로 끝내는" 가장 편한 로컬 셋업.
3. **GPU 서버 + 현재 노트북은 클라이언트** — LAN/사내에 GPU 박스를 두고 vLLM 등으로 서빙, 노트북의 OpenCode는 `baseURL`로 접속. 노트북은 그대로 두고 서버만 강화. → **`3.폐쇄망-GPU서버-아키텍처.md`**

---

## 5. 모델 교체(로컬에서 더 큰 모델 쓰기)

하네스 기본 모델은 `qwen2.5-coder:7b`입니다. 더 큰 모델을 받고 설정의 모델 참조를 일괄 교체합니다(예: 32B).

```bash
ollama pull qwen2.5-coder:32b
cd ~/work/ai-edu/harness
cp opencode.json opencode.json.bak
sed -i 's/qwen2.5-coder:7b/qwen2.5-coder:32b/g; s/Coder 7B/Coder 32B/' opencode.json
```

> 32B는 24GB VRAM(또는 64GB Mac)이 사실상 전제입니다. VRAM이 부족하면 CPU로 떨어져 매우 느려집니다. 모델 교체 상세는 `5.로컬교육-설치-활용.md` 3-1 참고.

---

## 6. 솔직한 결론

- **체험·교육이 목적이면** 지금 장비 + 7B(또는 3B)로 충분합니다. 목적은 워크플로우 학습입니다.
- **실제 코드 자동 편집을 안정적으로** 원하면 → **24GB NVIDIA + 32B** 또는 **64GB Apple Silicon**이 현실 최저선입니다.
- 다만 32B 로컬조차 **에이전트 신뢰도는 프런티어 클라우드 모델(Claude)에 못 미칩니다.** 그래서 "실제 작업"은 **`harness-claude-code`(클라우드 Claude 모델)** 가 비용 대비 가장 확실하고, 로컬은 학습·오프라인 용도로 병행하는 구성이 합리적입니다.
